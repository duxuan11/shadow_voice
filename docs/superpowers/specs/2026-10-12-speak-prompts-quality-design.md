> 状态：设计稿，待用户确认后进入实施
> 上游：[2026-10-11-speak-practice-design.md](./2026-10-11-speak-practice-design.md)（自由表达本体，已实现）

## 1. 背景与动机

自由表达已上线，但**题目本身不合格**。实测 `data/videos/01_出国旅行的日常/speak-prompts.json`：

| index | cn | en | 问题 |
|---|---|---|---|
| 2 | 这个东西是 | this guys is a | 残句 + 字幕转录错误 |
| 3 | 行李推车 | luggage trolley | 残句，与前一条本是同一句 |
| 4 | 用来放行李的 | where you put your bags | 残句，与上面两条同为一句 |

根因：`filterSubtitlesToPrompts` 是**逐行取字幕**的本地规则（长度 + 是否含 CJK/字母），完全不看上下文。
而字幕是**逐行转录**的，一句话常被切成多行，且**没有句末标点**（实测 01 全片 35 行无一以 `.?!。？！` 结尾），
所以"按标点断句"这类本地规则在这里根本用不上。

三个后果：

1. 大量题目是不成句的碎片，用户没法照着说一句完整的话；
2. 题目数量靠"字幕行数"堆（现为 40 句/视频），其中很多没有练习价值（专名、称呼、半句话）；
3. 场景扩展句混在末尾 5 条里，练习时**看不出来**它不是视频里的内容。

### 1.1 与上游设计的关系

| 上游决策 | 本次是否改 |
|---|---|
| 玩法（看中文说英文 + AI 评分）、评分端点与 prompt | 不变 |
| 预提取落盘、不在用户使用时临时调 AI | 不变 |
| `en` 只是参考答案之一，不要求逐字对齐 | 不变 |
| 本地规则过滤字幕（零 token） | **改为 AI 精选**（用户明确同意花 token） |
| `source: subtitle` 的 `en` = 字幕英文原文 | **改为 AI 改写后的地道英文**（字幕原文可能自身有错） |
| 每视频 ≤40 字幕句 + 5 扩展句 | **改为 ≤N 字幕句（9~20，按字幕量折半）+ 5 扩展句** |
| 练习页无来源/难度标识 | **新增**「场景扩展」与难度标识 |

### 1.2 已确认决策（用户原话）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 是否可用 token | 可以。AI 负责挑句、合并残句、改写地道英文 |
| 2 | 挑句标准 | 核心、重要、常用、日常生活的口语；"你觉得需要我多练的、对我有帮助的"；**不是每句都提取** |
| 3 | 每视频数量 | 字幕句：40 行字幕 → 真正的完整句 30 多句 → 提取 **20 句左右**；**短视频按比例**（已确认） |
| 4 | 场景扩展句 | **每视频 5 句**（用户所说"我的 5 句"专指扩展句）；日常/生活/常用场景 |
| 5 | 难度 | 随视频难度有简单/中等/难；"各个视频可以随机分配" |
| 6 | 送 AI 的字幕量 | **全量字幕**（现在截前 150 行，长视频挑不到全片最值得练的） |
| 7 | 扩展句标识 | 练习时有一个「场景扩展」标志即可（用户原话："有标志'场景扩展'等等即可"） |

> 本轮对话后续补充确认的三项（难度如何分配 / 数据重生由用户执行 / 清空已练记录）见 §10。

## 2. 产品定义

一句话：每条视频给出 **≤N 条精选字幕句（完整、地道） + 5 条场景扩展句**，练习时能看出哪些是扩展句、每句什么难度。

### 2.1 数量变化

| | 现在 | 改后 |
|---|---|---|
| 字幕句 | ≤40 上限（逐行，含碎片；实测 01 为 31 句） | ≤N（AI 精选 + 合并 + 改写） |
| 扩展句 | 5（混在末尾，无标识） | 5（末尾，带「场景扩展」标识） |
| 合计 | ≤45（实测 01 为 36） | ≤25 |

**N 的算法（本地确定性，不依赖 AI 判断）：** `N = min(20, max(5, round(字幕行数 / 2)))`

| 视频 | 字幕行数 | N | 目标难度 |
|---|---|---|---|
| 01_出国旅行的日常 | 35 | 18 | 简单（初级） |
| 02_洛基山脉湖边学英语 | 51 | 20 | 难（高级） |
| 03_中世纪法国村庄 | 35 | 18 | 中等（中级） |
| 04_简易英语电影:那是什么味道? | 61 | 20 | 简单（初级） |
| 05_一个意外的生日 | 218 | 20 | 简单（初级） |
| 06_如何在每天3点起来 | 26 | 13 | 中等（中级） |
| 07_和狗狗一起学英语 | 39 | 20 | 简单（初级） |
| 08_幸福的关键 | 22 | 11 | 难（高级） |
| 09_三十岁生活感悟 | 76 | 20 | 简单（初级） |
| 178_独自一人但不孤独 | 334 | 20 | 简单（初级） |
| 179_亲手建鸡舍 | 220 | 20 | 简单（初级） |
| 180_哥本哈根日记\|夏日时光、书籍与美食 | 255 | 20 | 中等（中级） |

合计上限：字幕句 220 + 扩展句 60 = **280 句**。
对齐用户例子：40 行字幕 → 20 句；22 行的短视频 → 11 句。N 是**上限**，AI 应宁缺毋滥。

## 3. 难度策略

- 视频 `info.json` 里已有 `level`（初级/中级/高级）与 `difficulty`(1~4)，映射：初级→**简单**、中级→**中等**、高级→**难**。
- 每条 prompt 带 `level: '简单' | '中等' | '难'`，AI 依据视频的目标难度打标，**允许上下浮动一档**（同一视频内可混合）。
- **已确认（2026-10-12）**：难度以视频档位为中心、同一条视频内允许混合三档（用户回复：“按照你说的”）。

### 4.2 产物 `speak-prompts.json`（version 2）

```json
{
  "version": 2,
  "videoId": "33650c75-6deb-4911-bea8-a9645e4a836b",
  "title": "出国旅行的日常",
  "level": "初级",
  "model": "deepseek-chat",
  "generatedAt": "2026-10-12T...",
  "prompts": [
    { "index": 0, "cn": "这个东西是行李推车，用来放行李的。", "en": "This is a luggage trolley, where you put your bags.",
      "source": "subtitle", "level": "简单", "subIndex": 2, "subIndexEnd": 4 },
    { "index": 18, "cn": "我订了一间带早餐的房间。", "en": "I booked a room with breakfast included.",
      "source": "ai_generated", "level": "中等", "subIndex": null, "subIndexEnd": null }
  ]
}
```

- `source`：由 AI 输出里**来自哪个数组**决定（`sentences[]` → `subtitle`，`extensions[]` → `ai_generated`），既不信任模型自报的标签，也不靠“有没有行号”猜——模型漏字段时会把字幕句误标成扩展句，那是会骗到用户的静默错误。
- `level`：「简单/中等/难」；兜底生成时为 `null`。
- `subIndex`/`subIndexEnd`：该题合并用到的字幕行范围（0-based），扩展句为 `null`。**当前无消费方**，保留用于人工抽查"合并对不对"。
- `version: 1 → 2`：`en` 语义变了（字幕原文 → AI 改写），旧文件不能当同一种东西读。

### 4.3 生成脚本规则（`npm run speak-prompts`）

用法不变：`--force` 全量重生 / `--video <id>` 单条 / `--dry` 只打印不写盘。

1. 读 `subtitles.json` + `info.json`，算 `N`，拼**全量**字幕（带 1-based 行号：`序号. English || 中文`）。
2. `isConfigured()` 为真 → 一次 AI 调用出全部题目（见 §5）。
3. 无 AI key → **不再伪造**：直接报错跳过（`status: 'skip', reason: 'AI 未配置，无法精选题目'`），并保留旧文件。
   理由：逐行碎片正是本次要修的问题，没有 AI 就不该生成新文件，宁可让页面走本地兜底。
4. 校验/归一化（§5.3）→ 落盘；已有文件跳过（除非 `--force`）。
5. 输出日志：`✓ <目录> 字幕句 18/18 扩展句 5/5 难度 简单×9/中等×7/难×2`；不合格的打出明确告警。
6. README「数据来源与处理」补一步 `npm run speak-prompts`（与既有第 6 步 `npm run wordcards` 并列）。

## 5. AI 提取（每视频一次调用）

### 5.1 输入

`视频标题` / `视频 level` / `N` / 全量字幕（带行号）。

### 5.2 System prompt 要点

- 你是在为「看中文说英文」口语练习出题，读者是想练日常口语的中文母语者。
- **挑句标准**：日常生活高频、口语常用、学了能直接用上的表达；宁可少而精，不合格的宁可不给（上限 N 条）。
- **跳过**：人名地名等专名、纯称呼/感叹、没有完整意思的残片、依赖大量背景才懂的句子、无法修复的转录噪声。
- **合并**：字幕是逐行转录，一句话常被切成多行。把属于同一句的相邻行合并成一句完整的话，并用 `lines` 字段标出用到的行号。
- **改写英文**：改成地道、自然、语法正确的现代口语英文；字幕可能有转录错误（如 `this guys is a` 需修正）。
  **只修正表达，不新增原文没有的信息。**
- **改写中文**：补成完整自然的中文，不要保留碎片语气；中文与英文必须同义。
- **场景扩展句**：另外新增 5 条围绕该视频场景（如航班/酒店/旅行/日常）的常用口语句，中英对照；不得与选出的字幕句重复或近似。
- **难度**：本视频目标难度为 X，每条标 `level`（简单/中等/难），以目标档为中心、允许上下浮动一档。
- 只输出一个 JSON 对象，不要 Markdown 代码块、不要解释。

### 5.3 输出契约与校验

**输出分为两个数组**，来源由**数组归属**决定，不依赖模型自报字段：

```json
{
  "sentences":  [ { "lines": [3, 5], "cn": "…", "en": "…", "level": "简单" } ],
  "extensions": [ { "cn": "…", "en": "…", "level": "中等" } ]
}
```

`sentences[]` → `source: 'subtitle'`（`lines` 可选）；`extensions[]` → `source: 'ai_generated'`（`subIndex` 恒 `null`）。

`normalizeSpeakPrompts(raw, { cap, targetLevel })`（纯函数，可单测）**按下列顺序**处理：

1. **分类**：`raw.sentences` → 字幕句；`raw.extensions` → 扩展句（非数组按空处理）。
2. **丢弃**：`cn`/`en` 为空、`cn` 无 CJK、`en` 无字母、`en` 词数 <3 或 >30。
3. **`level`** 不在 `{简单, 中等, 难}` → 置为 `targetLevel`；`targetLevel` 也无效 → `null`。
4. **`lines`** → 过滤成合法下标（整数且 `0 ≤ i < 字幕行数`）；取 `subIndex = min(lines) - 1`、`subIndexEnd = max(lines) - 1`。
   允许非相邻（模型可能跳过语气词行）——存的是**跨距**，抽查时按跨距对照。`lines` 缺失或全部非法 → **仍是字幕句**，只把 `subIndex`/`subIndexEnd` 置 `null`。
5. **去重**：`cn` 归一化（去空白、去标点）后完全相同 → 只留第一条；两条字幕句 `lines` 跨距完全相同时**保留但打日志**（模型重复出题，不因此丢题）。
6. **排序**：字幕句：有 `subIndex` 的按升序在前，无 `subIndex` 的按原顺序排在其后；扩展句全部在后——练习时扩展句集中在最后 5 条。
7. **截断**：字幕句 ≤ `cap`（**先排序再截断**，保证留下的是视频靠前的句子、且顺序与视频一致）；扩展句 ≤ 5。

**重试与“不编造”：**

| 情况 | 处理 |
|---|---|
| JSON 解析失败 | `generateJsonWithRetry` ≤3 次（沿用） |
| 无字幕句，或扩展句 <5 | 带失败原因重试 1 次 |
| 重试后扩展句 3~4 条 | 落盘 + 打印告警（**不编造句子凑 5**），交付说明里列出是哪儿条视频 |
| 重试后扩展句 <3 或无字幕句 | 判该视频失败，**保留旧文件**，脚本非 0 退出 |
| AI 未配置 | 整条跳过并报错（§4.3 第 3 条） |

### 5.4 Token 量级

单视频输入 ≈ 字幕全量（`178` 最长 334 行 ≈ 6~8k token），输出 ≈ 25 条 ≈ 2k token。12 条视频一次性重生，
deepseek-chat 量级可忽略。用户已确认"可以使用 token"。

## 6. 页面标识（`SpeakPracticePage.jsx`）

中文卡片上方一行小标签（现有「看中文，说英文」标签旁）：

```
┌────────────────────────────────────────────┐
│ ← 返回    自由表达 · 出国旅行的日常   3/25   │
├────────────────────────────────────────────┤
│   [场景扩展] [中等]                          │   ← 仅扩展句显示「场景扩展」；level 存在才显示难度
│         这个东西是行李推车，用来放行李的。    │
│                                            │
│        [🎤 点击录音 / ⏹ 点击停止]           │
│        识别结果（可编辑文本框）              │
│            [🔍 解析]                        │
└────────────────────────────────────────────┘
```

- 标识位置：中文卡片内、中文句子**上方**（题目区，不剧透答案）。
- 「场景扩展」：`source === 'ai_generated'` 才显示（青色/紫色系，与难度标签区分）。
- 难度：`level` 存在才显示（简单=绿 / 中等=琥珀 / 难=玫红）。`level` 为 `null`（兜底题目）→ 不渲染。
- 其余交互（录音、解析、评分展示、上一句/下一句、进度）**完全不变**。

## 7. 兜底路径（`speak-prompts.json` 缺失时）

**本次不给兜底加合并规则**。原计划"按标点合并相邻行"经实测不可行：字幕无句末标点，本地启发式合并会**并错句子**。
实测（`01`，规则：累计英文 ≥6 词且结尾不是连接词/介词则收句）：

```
[1-3] so let's take the lift this guys is a luggage trolley   ← 把两句并成了一句（错）
[4-6] where you put your bags on normally the concierge takes your bags   ← 并错（错）
[7-8] the concierge in the hotel is like your personal assistant   ← 并对
```

片段至少还是"原话"，并错则产生**视频里根本不存在的句子**，比碎片更糟。故兜底维持现状语义：

- 逐行过滤（长度/CJK/字母）+ 上限也用同一个 `N`；
- 输出 `source: 'subtitle'`、`level: null`、`subIndex: i`、无 `subIndexEnd`；
- 页面据此不渲染难度标签，**只显示「场景扩展」以外的无标识状态**（即兜底题目没有难度标识）。

> 兜底是罕见降级路径（文件缺失），不承担"题目质量"职责；质量由预提取产物保证。

## 8. 已知影响：已练记录错位

题组从 45 条缩到 ≤25 条，`practice_records.data.speak` 里存的**旧序号含义已变**。

- 不会崩：`firstUnpracticedIndex` 遍历 `0..n-1`，全练过返回 0（不会返回越界下标）。
- 但会**误显示"全部练过"**（旧记录 0~24 恰好覆盖新题组的 0~24）。
- 处理：本次**不做自动迁移**；推荐重生数据后一次性清空 `practice_records` 的 `speak` 字段（见 §10 待确认项）。

## 9. 交付与上线路径（`data/` 不入库）

`.gitignore` 里有 `/data/`，所以 **12 个 `speak-prompts.json` 不是代码交付物**：它们只存在于某个环境的 `DATA_DIR`
（本地 `./data`；NAS 上是 docker-compose 挂载的 `./data`）。练习记录 DB 也在同一目录：`data/shadow_voice.db`（`SHADOW_VOICE_DB` 可覆盖）。
这与既有 `npm run wordcards` 的产物 `wordcard.json` 完全同类，沿用同一条路子：

| 交付物 | 谁做 |
|---|---|
| 脚本 / 纯函数 / 练习页 / 单测 / README | 本计划实现（进 git） |
| 12 条 `speak-prompts.json` 重生 | **用户自己在他练习的环境里跑**（已确认）；命令要带 `--force`，否则现有文件会被跳过 |
| 已练记录清理 | 本计划提供 `scripts/reset-practice-task.mjs`（已确认要清），由用户对目标 DB 执行 |

> ⚠️ **必须带 `--force`**：`npm run speak-prompts` 默认跳过已存在的 `speak-prompts.json`，不带参数跑完会什么都不变（用户容易踩）。README 里要写成 `npm run speak-prompts -- --force`。
> 若练习环境的 `DATA_DIR`/DB 不在当前仓库目录（如 NAS 上的 docker 挂载卷），需先指过去：`DATA_DIR=… SHADOW_VOICE_DB=… npm run speak-prompts -- --force`。

两个坑（写进计划，避免“代码上了、问题没修”）：

- **`data/` 未重生时页面继续读旧 v1 文件**：v1 里那 5 条 `ai_generated` 会被打上「场景扩展」标识，但没有难度标签、字幕句仍是碎片。
- **`vite.config.js` 给 `/data/` 设了 `Cache-Control: max-age=3600`**：验证时旧 JSON 可能被浏览器缓存 1 小时，需硬刷新。
